# P0 戰鬥 UI／UX 規格

## 目標

手機上的主要操作不是逐張搬牌，而是：

```text
先整理 13 張牌
→ 選出一組 3 張或 5 張
→ 一次放入指定墩位
→ 檢查三墩順序
→ 確認戰鬥
```

## 手牌排序

排序只改變畫面排列，不改變牌的實體身份、抽牌順序或牌陣位置。

提供兩種排序：

1. **依點數**：A、2～10、J、Q、K；同點數維持原始牌序。
2. **依花色／點數**：水、火、風、地，再依點數排列；同牌維持原始牌序。

手機上使用一個清楚的排序列，不使用藏在選單裡的排序功能：

```text
排序：點數｜花色
```

## 選牌與分墩

- 點擊手牌切換選取狀態。
- 可以同時選取多張牌，選取的牌會有黃色外框與編號。
- 最多同時選 5 張，避免誤選與畫面失去控制。
- 選取 3 張時，只啟用頭墩操作。
- 選取 5 張時，只啟用中墩與尾墩操作。
- 其他張數顯示還需要選幾張，不提供模糊的不可用按鈕。
- 一次放入後清空選取，並顯示「已放入頭／中／尾墩」。

操作列只在有選牌時顯示主要行動：

```text
已選 3 張      放入頭墩
已選 5 張      放入中墩／放入尾墩
```

## 墩位與修改

- 頭墩固定 3 張，中墩與尾墩固定 5 張。
- 已放入墩位的牌可以再次點選。
- 同一時間只選一個區域的牌，避免把手牌和不同墩位混成不明確的操作。
- 從墩位選取完整墩後，主要操作變成「退回手牌」。
- 退回後才能重新整理並放入其他墩位。
- 不使用拖曳作為唯一操作；拖曳可在未來作為桌面輔助，但手機點選流程必須完整。

## 即時回饋

畫面固定顯示一條短提示：

```text
先選 3 張牌組成頭墩，或選 5 張牌組成中／尾墩。
```

依選取數量改變：

```text
已選 2 張，再選 1 張即可放入頭墩。
已選 4 張，再選 1 張即可放入中墩或尾墩。
頭墩已完成：一對。
目前分墩不合法：中墩必須大於頭墩。
```

不在玩家畫面顯示 seed、節點 ID、測試用開發標籤。

## 手機版面順序

```text
敵人／目前目標
↓
目前目標／三墩區：頭墩、中墩、尾墩
↓
手牌
↓
排序列
↓
主要操作／確認這副牌
```

手牌是主要互動區，排序和分組按鈕靠近手牌；確認按鈕固定在底部，但只有 3／5／5 合法時才啟用。中尾互換、整墩收回與快速補齊屬於「快速修正」次要操作，不與主要放入操作競爭。

## 戰鬥首屏與結果

首屏優先讓玩家完成一個決策：看敵方／目前目標 → 整理手牌 → 放入三墩 → 確認。候選敵牌、Boss 規則、遺物詳情與角色技能說明可放在不依賴 hover 的可展開詳情區。

戰鬥結果規則：三墩平手目前視為戰敗，會沿用本場節點的命數損失與重試規則；畫面必須顯示「三墩平手（視為戰敗）」及明確本場損失，不能只顯示中性的「平手」。

「放棄這趟遠征」是整趟 Run 的危險操作，必須二次確認；確認後清除 active Run、回到營地、不扣命、不取得未領取獎勵。

## 驗收條件

- 排序不改變 13 張牌的 ID 集合。
- 相同 seed 的牌，兩種排序都能回到同一組牌。
- 可以從手牌選 3 張一次放入頭墩。
- 可以從手牌選 5 張一次放入中墩或尾墩。
- 選 4 張時不會誤放入任何墩位，提示還需要 1 張。
- 已放入的完整墩可以一次退回手牌。
- 每次批次移動後都重新驗證 3／5／5 與墩位順序。
- 手機寬度下主要按鈕維持可觸控尺寸，不依賴拖曳。
- Ripple／Spark／Flow 使用後 reload，重抽次數、頭墩加成與元素墩覆寫仍影響本次 resolve；戰鬥完成後 pending state 清除。

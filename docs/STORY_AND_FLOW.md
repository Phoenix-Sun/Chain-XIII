# Chain XIII 劇情與流程基準

## 定位

Chain XIII 是一款手機優先的角色抽卡＋卡牌 Roguelike 遊戲。

- 畫面：可愛、清楚、像素化，參考 Kairosoft 的場景與回饋方式。
- 流程：單向節點、一次做一個選擇，參考 Slay the Spire。
- 核心：抽 13 張牌、調整花色、排成頭 3／中 5／尾 5、擊敗怪物與 Boss。
- 文字：白話、短句，不為了世界觀硬塞新名詞。

## 世界觀包裝

世界各地的元素力量開始失控，怪物變得更強。

玩家帶領目前擁有的角色踏上遠征，沿路打倒怪物，取得基因鏈，鍊成花色配置，最後挑戰路線上的 Boss。

故事只需要回答：

1. 為什麼要遠征：元素失控，需要找出原因並往前推進。
2. 為什麼打怪：怪物會阻擋路線，也可能掉落基因鏈。
3. 為什麼鍊成：基因鏈可以改變牌的花色，影響下一場十三支。
4. 為什麼打 Boss：Boss 是這條路線最後的挑戰。

不要用劇情限制角色取得順序。玩家可以在第一趟 Run 前透過水晶抽到多名角色。

## 角色與抽卡

新帳號至少有 1 名預設角色。

角色收藏透過以下方式擴充：

- 完成遊戲取得水晶。
- 使用水晶抽卡。
- 未來可加入活動或其他獎勵，但不改變基本模型。

帳號角色收藏和本次出戰隊伍是兩件事：

```text
ownedCharacterIds       玩家已擁有的全部角色
partyCharacterIds       這趟 Run 選出的角色
```

每趟 Run：

- 至少選 1 名角色。
- 最多選 3 名角色。
- 只有預設角色也可以開始。
- 如果玩家已抽到多名角色，第一趟就可以直接選 2～3 人。
- 不用劇情強迫玩家依序解鎖第二、第三名角色。

## 玩家流程

```text
營地
→ 選擇本次出戰角色
→ 選擇路線節點
→ 戰鬥／事件／獎勵
→ 取得基因鏈或其他獎勵
→ 鍊成或調整配置
→ 繼續選路
→ 挑戰 Boss
→ 結算水晶與其他永久收益
→ 抽卡或開始下一趟 Run
```

每個畫面只處理目前最重要的事情：

- 營地：要開始什麼？
- 隊伍：這趟帶誰？
- 路線：下一站去哪裡？
- 戰鬥：這 13 張牌怎麼排？
- 獎勵：要拿什麼？
- 鍊成：要不要改變花色配置？
- 結算：這趟拿到什麼？

## 營地

營地是流程入口，不是城市經營系統。

可以有像素場景、角色活動、短訊息與可點擊物件，但每個物件都必須直接服務遊戲：

- 隊伍帳篷：選擇出戰角色。
- 路線桌：查看下一個節點。
- 鍊成篝火：合成基因鏈與調整花色。

暫時不做：

- 居民數
- 城市熱度
- 城市日期
- 沒有用途的金幣或聲望
- 城市建設與升級
- 開發卷宗作為玩家主選單

## 文案規則

優先使用：

```text
角色、怪物、Boss、遠征、路線、戰鬥、基因鏈、鍊成、花色、元素
```

避免為每個功能創造新稱呼。必要的世界觀詞彙只作背景，不取代玩家已經看得懂的系統詞。

範例：

```text
前方：火屬怪物
可能掉落：火系基因鏈

Boss：熔岩龜
特性：尾墩容易形成同花

取得：火－火－風 基因鏈
```

## 不可違反的 UX 原則

- 不在開場假設玩家一定有 3 名角色。
- 不在劇情中寫死下一個一定會取得哪名角色。
- 不在戰鬥畫面顯示無關的城市數值、完整圖鑑或開發進度。
- 不把 seed、節點 ID、測試用數值放在正式玩家畫面。
- 主要按鈕只有一個，次要資訊收進短面板或抽屜。
